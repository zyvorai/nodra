# Roadmap

## Current (main)

Offline WAL, backpressure, local routes, MQTT QoS 0/1/2 (optional broker TLS and client certificates via `mqtt_cert_file` / `mqtt_key_file` / `mqtt_require_client_cert`), transactional cloud ACK, concurrent webhook dispatch, replayable DLQ, original event time, device twins, CSR site certificates, site revocation, Docker reconciliation, Modbus TCP building block + **poller connector**, connector registry, orange embedded dashboard with **console write actions**, chaptered login, activity Logs, A–Z `nodra-sim`, demo Helm/Compose, configurable ports, **viewer/admin RBAC**, optional **Postgres fleet store** (`NODRA_STORE=postgres`; every fleet read hits PostgreSQL, and updates use a `revision` column so replicas cannot silently overwrite each other), zyvor.dev product/docs pages, **Nodra→Relay Accept bridge** (`nodra-relay-bridge`), **local route filter/transform rules** (`internal/transform`), **OPC-UA adapter** (`connectors/opcua`, SecurityPolicy None or Basic256Sha256 Sign/SignAndEncrypt, anonymous user token, Read + Write + Subscribe/MonitoredItems (poller `mode: "poll"` or `"subscribe"`), plus GetEndpoints/FindServers/Browse), **durable audit log + export** (`internal/audit`, file or Postgres, `GET /api/v1/audit(/export)`, `nodractl audit list|export`), **certificate rotation + CRL** (`internal/pki`, nodrad-initiated re-key via `POST /api/v1/sites/{id}/rotate`, unauthenticated `GET /api/v1/ca/crl`, `certificate_expiring` alerts), **NATS bridge** (`connectors/nats`, dependency-free subscribing client — Zenoh explicitly deferred, see `docs/NATS_BRIDGE.md`), **generic serial/USB connector** (`connectors/serial`, delimiter- or idle-gap-framed passthrough poller sharing termios config via `internal/serialport` with Modbus RTU, Linux-only + build-tag stub), **fleet policy packs v1** (`internal/policy`, `allowed_images` allowlist only — no RBAC-rule or alert-threshold packs — enforced at deployment create/patch, see `docs/POLICY_PACKS.md`), **OIDC console login** (`internal/oidc`, RS256-only, a configured group claim maps to the existing admin/viewer roles — no user directory, no multi-tenant orgs), **cosign-verify-before-pull + health-gated rollback** (agent shells out to an externally-installed `cosign` binary before `docker pull`; `signature_mode` enforce/warn/skip, default warn; `POST /api/v1/agent/deployments/{id}/rollback` reverts to the last known-good image/version on binary Docker-health failure past `deploy_health_grace` — not staged/canary campaigns), **Postgres fleet consistency and concurrent delivery claiming** (`NODRA_STORE=postgres`: `store.PostgresStore` reads every fleet document from PostgreSQL and updates it with `revision` so replicas cannot silently overwrite each other; a cross-replica test covers that. `internal/queue.PostgresQueue` implements `queue.Claimer` so every replica's `worker()` claims deliveries concurrently via `UPDATE ... RETURNING id`, with `DeliveryClaimLease` default 90s. This is not full HA: file mode stays one replica, Helm refuses to scale it, and multi-day soak, PITR, and the rest of the v1.0 gates are still open), **multi-tenant orgs, full data isolation** (`model.Org`, `GET|POST /api/v1/orgs`, `GET|DELETE /api/v1/orgs/{id}`, global-admin-token-only; an org gets its own enrollment token and its own admin/viewer bearer tokens, resolved the same way as the global ones; org-scoped list/read/mutate filtering (`callerCanSeeSite`/`callerCanMutateSite`) now covers sites, devices, twins, routes, deployments, policy packs, alerts, events, activity, audit, and dead letters — a fleet-wide/unscoped resource (empty `site_id`) is still visible to every org but mutable only by the global admin token; `overview`'s per-entity counts are org-scoped too, except `pending_deliveries`/`delivery_queue_bytes`/`dead_letters`, which come from `queue.Stats()` and have no per-site breakdown, so they stay fleet-wide totals — see `docs/ARCHITECTURE.md`'s "Multi-tenant orgs" section for the exact, still-not-absolute scope, e.g. audit/DLQ listing org-filters by post-filtering a page rather than the query itself, so a page can come back thinner than its limit for an org-scoped caller), **MQTT persistent sessions** (`internal/mqtt`, `Broker.EnableSessions`; `CleanSession=0` keeps a durable per-client queue that replays missed QoS 1 messages with `DUP` and replays QoS 2 through the full handshake; subscription lists are in-memory and do not survive a broker restart; `CleanSession=1` discards prior state), **MQTT QoS 2 in both directions** (publishing clients get the full `PUBLISH`/`PUBREC`/`PUBREL`/`PUBCOMP` exactly-once handshake; delivery is deferred to `PUBREL` so retransmits never double-deliver; subscribers get the same handshake with in-flight tracking), **Zyvor OTA contract, wired** (`pkg/ota`, see `docs/OTA_INTEGRATION.md` — an OTA request/status rides the existing Device Twin desired/reported mechanism under a reserved `ota` key, so it's durably stored and delivered via nodrad's existing twin polling, not a new path; `POST/GET /api/v1/devices/{id}/ota`, `POST /api/v1/agent/devices/{id}/ota/status` (`409` on an illegal lifecycle transition, `ota_failed`/`ota_rolled-back` alerts), nodrad-local `POST /v1/devices/{id}/ota/status`; **staged multi-site canary campaigns** via `model.OTACampaign` and `/api/v1/ota/campaigns` create/list/get/start/promote/abort).

## Next

- ~~OPC-UA Basic256Sha256 security~~ — Have (real secure-channel crypto, Go
  standard library only: RSA-OAEP asymmetric OpenSecureChannel with an
  RSA-SHA256 chunk signature, P_SHA256 key derivation from the channel
  nonces, and AES-256-CBC + HMAC-SHA256 symmetric MSG framing for both
  `Sign` and `SignAndEncrypt`; CreateSession/ActivateSession send the client
  certificate and nonce and verify the ServerSignature. Configured with
  `security_policy` / `security_mode` / `client_cert_path` /
  `client_key_path` / `server_cert_path` on the poller and
  `Client.Security`; the None/anonymous path is unchanged, and selecting
  Basic256Sha256 without usable certificates fails with an actionable
  error). Verified against an in-repo mock server that implements the
  server half from the raw primitives, not against a certified commercial
  stack, and not through a conformance suite. Still out of scope:
  non-anonymous user identity tokens (username/password, X.509 — the token
  stays anonymous under every policy), other policies (Basic256, Aes128Sha256RsaOaep,
  Aes256Sha256RsaPss), channel-token renewal on a long-lived channel, and
  multi-chunk messages.
